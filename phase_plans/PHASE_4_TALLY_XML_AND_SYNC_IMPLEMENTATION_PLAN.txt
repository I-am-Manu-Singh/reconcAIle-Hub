1. PROBLEM STATEMENT & OBJECTIVE
--------------------------------------------------------------------------------
Phases 1-3 took an unstructured bank statement PDF, extracted tabular transaction rows,
classified cryptic narrations to verified chart-of-accounts ledgers, and provided an
accountant review grid for approval.

Phase 4 fulfills the end goal:
Converting all verified bank transactions into standard-compliant, double-entry
accounting vouchers in Tally ERP 9 and TallyPrime:
1. Direct Native Sync: Sending HTTP/XML requests directly into a running local Tally instance (port 9000).
2. Standalone Tally XML Export: Generating an offline `.xml` file ready for "Import Data -> Vouchers" in Tally for air-gapped or remote accountant workstations.
3. Local Audit Trail: Updating the local SQLite `mirror_vouchers` and `bank_transactions` status to `IMPORTED` with Tally master IDs and timestamps.


2. TALLY DOUBLE-ENTRY ACCOUNTING RULES FOR BANK TRANSACTIONS
--------------------------------------------------------------------------------
Tally enforces strict XML element tags, sign conventions, and positive/negative indicators:

A. Payment Voucher (Withdrawals / Money Out from Bank):
   - Voucher Type: `<VOUCHER VCHTYPE="Payment">`
   - Party / Expense Ledger Entry (Debit):
     * `<ISDEEMEDPOSITIVE>Yes</ISDEEMEDPOSITIVE>`
     * `<AMOUNT>-${amount}</AMOUNT>` (Negative value indicates Debit in Tally XML)
   - Bank Account Ledger Entry (Credit):
     * `<ISDEEMEDPOSITIVE>No</ISDEEMEDPOSITIVE>`
     * `<AMOUNT>${amount}</AMOUNT>` (Positive value indicates Credit in Tally XML)
   - Banking Details:
     * `<BANKALLOCATIONS.LIST>` with `<TRANSACTIONTYPE>`, `<INSTRUMENTNUMBER>`, `<PAYMENTFAVOURING>`

B. Receipt Voucher (Deposits / Money In to Bank):
   - Voucher Type: `<VOUCHER VCHTYPE="Receipt">`
   - Bank Account Ledger Entry (Debit):
     * `<ISDEEMEDPOSITIVE>Yes</ISDEEMEDPOSITIVE>`
     * `<AMOUNT>-${amount}</AMOUNT>` (Debit in Tally XML)
   - Customer / Income Ledger Entry (Credit):
     * `<ISDEEMEDPOSITIVE>No</ISDEEMEDPOSITIVE>`
     * `<AMOUNT>${amount}</AMOUNT>` (Credit in Tally XML)

C. Contra Voucher (Internal Transfers between Bank & Cash):
   - Voucher Type: `<VOUCHER VCHTYPE="Contra">`
   - Used when Cash is withdrawn from Bank or deposited to Bank, or transferred to another bank account.

D. Split Allocations (Multi-ledger breakdown):
   - If a ₹1,18,000 payment is split across Consulting (₹1,00,000) and GST (₹18,000):
     * Emits multiple `<ALLLEDGERENTRIES.LIST>` blocks for each split debit line.
     * Single balancing `<ALLLEDGERENTRIES.LIST>` block for the full Bank credit.

5. TALLY RESPONSE PARSER & ERROR HANDLING
--------------------------------------------------------------------------------
File: `electron/main/tally/tallyImportResponseParser.ts`

When Tally receives the XML payload, it responds with:
```xml
<RESPONSE>
  <CREATED>148</CREATED>
  <ALTERED>0</ALTERED>
  <DELETED>0</DELETED>
  <COMBINED>0</COMBINED>
  <IGNORED>0</IGNORED>
  <ERRORS>0</ERRORS>
  <LINEERROR>Ledger 'Acme Industrial' does not exist!</LINEERROR>
</RESPONSE>
```

Handling Logic:
1. If `<ERRORS>0</ERRORS>` and `<CREATED> > 0`:
   - All vouchers successfully created in Tally.
   - Batch status set to `SUCCESS`.
2. If `<ERRORS> > 0`:
   - Extracts all `<LINEERROR>` descriptions.
   - Matches the error to the specific transaction row (e.g. missing ledger, locked period).
   - Returns granular failure list to the UI so the user can fix the specific ledger and retry only failed vouchers without duplicating successful ones (idempotent via GUID).


6. IPC & PRELOAD API SPECIFICATION
--------------------------------------------------------------------------------
File: `electron/main/ipc/tallyIpc.ts` & `electron/preload/preload.ts`

New IPC Handlers:
1. `tally:import-statement-vouchers`
   - Payload:
     ```typescript
     {
       companyName: string;
       bankLedgerName: string;
       vouchers: VerifiedVoucherRow[];
     }
     ```
   - Invokes direct HTTP import to Tally.
   - Returns `{ success: boolean; createdCount: number; errorCount: number; errors: string[] }`.

2. `tally:export-statement-vouchers-xml`
   - Payload:
     ```typescript
     {
       companyName: string;
       bankLedgerName: string;
       vouchers: VerifiedVoucherRow[];
       suggestedFileName?: string;
     }
     ```
   - Opens native save dialog and saves formatted Tally XML file.

Preload API:
```typescript
desktop.tally.importStatementVouchers(
  companyName: string,
  bankLedgerName: string,
  vouchers: VerifiedVoucherRow[]
): Promise<TallyImportResult>;

desktop.tally.exportStatementVouchersXml(
  companyName: string,
  bankLedgerName: string,
  vouchers: VerifiedVoucherRow[]
): Promise<{ filePath: string | null; exportedCount: number }>;
```
